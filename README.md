# ASUS Battery Limiter 2.0 — установлен на ASUS UX310UAR

**Статус на 23.10.2026:** системная служба установлена и активна. Пользовательский интерфейс обновлён отдельно; защищённая root-копия контроллера зарядки при этой правке не изменялась.

## Режимы

1. **100%** — штатная зарядка до 100%.
2. **Ресурс аккумулятора** — ниже MIN разрешить заряд до MAX; внутри диапазона не начинать новый цикл; начатый цикл довести до MAX.
3. **Без зарядки** — только если есть самостоятельный аппаратный переключатель charging_enabled. На ASUS UX310UAR его нет: при выборе интерфейс объясняет недоступность и не меняет аппаратное управление. Малый верхний порог не является полным отключением зарядки.

MIN/MAX определяются при включении режима 2 и после завершения каждого цикла. Для обнаруженного профиля ASUSTeK / ASUS Battery / Li-ion применяется верхняя граница **60%**, подтверждённая ASUS для работы от адаптера. Нижняя граница **50%** — инженерная эвристика для сокращения подзарядок, а не рекомендация ASUS. Последующие циклы: 50–60%, 49–59%, 48–58%; затем повтор. Изменение на 1–2 процентных пункта — экспериментальный консервативный выбор, а не доказанный способ продления ресурса. При достоверном износе >20% границы немного уменьшаются.

Для неизвестного производителя/химии режим 2 не применяется. Нет данных о точной ревизии элементов и температуре; не следует выдумывать их.

У ноутбука доступен только charge_control_end_threshold. Контроллер реализует гистерезис программно: в ожидании аппаратный верхний порог равен MIN; после начала цикла — MAX. **Подтверждение чтением установленного порога не доказывает соблюдение его микропрограммой.** Некоторые ASUS игнорируют часть значений.

## Файлы и процессы

- battery-limiter — Python, режимы, расчёт и уведомления.
- tests/test_battery_limiter.py — проверки на поддельных файлах sysfs.
- Установленная служба — один root-owned фоновый контроллер, опрос 15 секунд. Он исполняет только защищённую копию программы из /usr/local/libexec, а не изменяемый пользователем файл из ~/bin.
- GTK3 StatusIcon (X11/XEmbed) и notify-send используются без новых зависимостей. AppIndicator в Xfce не передавал подсказки меню через D-BusMenu; поэтому для этой графической сессии используется местное GTK-меню. Gtk.StatusIcon устарел и при миграции на Wayland потребует замены.

Трей сообщает о подтверждённом начале зарядки, достижении границ и 100%, без повторов. Если графический сеанс закрыт, управление продолжится, но уведомления будут недоступны.

## Интерфейс (23.10.2026)

Меню: «Полный заряд», «Ресурс батареи», «Без зарядки» — без номеров и процентов. При наведении на пункт отображается краткое объяснение с текущими MIN/MAX; при наведении на иконку Xfce — активный режим. Цвет SVG-иконок наследуется от GTK-темы через символический набор (семь векторных файлов, создаются в ~/.local/share/icons/hicolor/scalable/apps).

Согласованная раскадровка: `○` — пустой круг (только контур), `●` — закрашенный круг. Полный заряд, 7 кадров: `○○○ → ●○○ → ○●○ → ○○● → ●○● → ○●● → ●●●`; ресурс батареи, 4 кадра: `○●○ → ○○● → ○●○ → ●○○`; без зарядки, 1 кадр: `○○○`. Кадры меняются каждые 1,5 секунды (вместо 550 мс): полный цикл ресурсного режима — 6 секунд; заливка и контур используют цвет символьных иконок текущей темы. Увеличен просвет в пустых кругах для различимости в системном трее.

PrintScreen этой доработкой не менялся: отдельная задача. Интерфейс запускать командой battery-limiter --tray либо автозапуском Xfce. Резервная копия пользовательского кода до смены GTK: ~/bin/battery-limiter.appindicator-before-20261023.bak.

## Проверка без установки

    python3 -m unittest discover -s tests -v
    python3 ./battery-limiter status

На ноутбуке зафиксировано 22.10.2026: 73%, Not charging, верхний порог 75%; 36 циклов; energy_full=48028000, energy_full_design=44460000. Отношение >1 исключено из оценки износа как недостоверное.

## Установка и восстановление

Проверка чтения/записи значений 48, 49, 50, 58, 59 и 60 прошла 22.10.2026 с возвратом порога 75%; затем новая служба установлена локально. Повторная установка без необходимости не требуется.

    sudo python3 battery-limiter install --user oem

Установщик создаёт резервные копии исходной службы, программы и конфигурации с суффиксом .v1.bak; заменяет службу и пользовательский исполняемый файл. При ошибке запуска восстанавливает прежний файл службы. Затем перезапустить значок в трее и проверить:

    battery-limiter status
    battery-limiter mode 1
    battery-limiter mode 2
    battery-limiter mode 3

На этом UX310UAR команда mode 3 должна вернуть ошибку без изменения действующей политики.

**Откат:** от администратора вернуть исходный /etc/systemd/system/battery-limiter.service.v1.bak на место unit-файла, выполнить systemctl daemon-reload и systemctl restart battery-limiter. Вернуть пользовательские резервные копии ~/bin/battery-limiter.v1.bak и ~/.config/battery-limiter.json.v1.bak, перезапустить трей. Снятый аппаратный порог не сбрасывать без явного решения.
